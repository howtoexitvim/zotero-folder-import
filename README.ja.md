Zotero Folder Import は、PDF と EPUB のフォルダを管理された添付ファイルとして取り込むための Zotero 10 プラグインです。

フォルダ構造はそのままネストされたコレクションになります。ファイル名は保持され、メタデータの検索やリネームは一切行いません。Finder で見えているものが、そのまま Zotero に入ります。

サードパーティのランタイム依存なし、ネットワーク通信なし、テレメトリなし。

## インストール

[releases ページ](https://github.com/howtoexitvim/zotero-folder-import/releases)から `.xpi` をダウンロードし、Zotero で **Tools → Add-ons → 歯車アイコン → Install Add-on From File…** を開いて、そのファイルを選択してください。

あとは任意のコレクションを右クリックし、フォルダインポートの項目を選ぶと、取り込むディレクトリツリーを指定できます。

Zotero 10 が必要です。現在のリリースは **v0.1.21** です。

自動更新のチャンネルはありません。Zotero 10 はインストール可能なすべての manifest に `update_url` を要求するため、ビルドでは更新サービスを置けない予約済みの `.invalid` アドレスを指しています。新しいバージョンも同じ手順でインストールしてください。

## ファイルの判定方法

判定基準はひとつだけです。**取り込み先のコレクションに同名のファイルがあるかどうか**。ファイルマネージャーと同じ考え方で、内容を読むことも、ライブラリ全体を走査することもありません。

| 状態 | 判定基準 | 動作 |
| --- | --- | --- |
| **New** | 取り込み先コレクションに同名ファイルがない | Zotero storage にコピーし、元のファイル名を保持 |
| **Conflict** | 取り込み先コレクションに同名ファイルがある | Replace / Keep Both / Ignore をユーザーが選択 |

インポートのたびに**独立した添付ファイル**が作られます。同じ PDF を 2 つのコレクションに取り込めば、独立した 2 つのアイテムと 2 つの storage ディレクトリになり、一方で削除・注釈・改題をしても、もう一方には影響しません。その代わり場所ごとにファイルのコピーを 1 つずつ持つことになります。Finder で同じファイルを 2 つのフォルダにコピーするのと同じトレードオフです。

削除の挙動は押すキーで決まります。コレクション内で Delete を押すと `removeFromCollection` が呼ばれ、そのコレクションからアイテムを外すだけです。Cmd+Delete、または My Library のルートでの削除は `trashTx` を呼び、アイテム本体をゴミ箱へ移します。確認メッセージはそれぞれ "Remove from Collection" と "Move to Trash" になります。

Replace は新しい添付ファイルを先にインポートし、それが成功してから古いものをゴミ箱に移します。インポートが失敗しても、どちらも失うことはありません。

インポートは途中でキャンセルできます。インポート中は Cancel が停止操作に変わり、ループが毎周フラグを確認します。すでに取り込まれたものはそのまま残り、残りはスキップされ、結果画面にはキャンセル済みと表示されます。未解決の競合が残っているプランは、エグゼキュータが実行を拒否します。

## MD5 で照合しない理由

かつては「Zotero は内部的に MD5 でファイルを識別しているので、ハッシュを照合しないと Cmd+Delete でもう一方まで消えてしまう」と考えていました。ソースを確認した結果これは誤りだと分かり、0.1.18 で判定を純粋なファイル名に変更しました。

- 添付ファイルの storage ディレクトリは**ランダムなアイテムキー**で分かれており、内容とは無関係です。同じ内容の PDF 2 つは別々のディレクトリに、それぞれ物理的なコピーとして存在します。
- `importFromFile` にハッシュによる**重複排除のロジックは一切ありません**。
- Duplicate Items ビューは **ISBN / DOI / タイトル + 著者**で照合しており、MD5 は使いません。
- MD5（`attachmentSyncedHash`）は**storage sync 専用**で、ファイルを再アップロードする必要があるかを判断するためのものです。削除や重複排除とは関係ありません。

したがって独立したコピー同士が影響し合うことはありません。以前観測された「一方を削除するともう一方も消える」現象は、初期の本プラグインが `linkExisting()` で単一のアイテムを使い回していたことが原因で、その経路はすでに削除されています。

## 既知の Zotero 10 の制約

これらは本プラグインの選択ではなくプラットフォーム側の制限です。他のプラグイン作者の手間を省けるかもしれないので記録しておきます。

- プラグインのダイアログは、登録済みの `chrome://` URL から開く必要があります。インストール済み XPI の `rootURI` は `jar:` URL で、そこから開いたウィンドウはスタイルもスクリプトも読み込めず、空白のまま描画されます。
- ダイアログの body は純粋な XUL でなければなりません。HTML 要素が 1 つでも混ざると、パーサーが body 全体を破棄します（`documentElement.children.length === 0`）。
- プラグインが同梱する Fluent ファイルは、メニューでもダイアログでも解決されません。そのため文言はすべてスクリプトから直接設定しています。
- Zotero のソースは `/Applications/Zotero.app/Contents/Resources/app/omni.ja` にあり、展開すれば API を推測せずに確認できます。

## コマンド

```bash
npm install
npm test
npm run typecheck
npm run build
npm run verify
```

`npm run build` は `dist/folder-import-<version>.xpi` を生成し、バージョンは `addon/manifest.json` から取得します。ビルドには TypeScript と esbuild、テストには Vitest を使用し、57 件のテストがすべてパスします。

## アーキテクチャ

- `src/core/`: ファイルシステムに依存しないスキャナ、取り込み先リゾルバ、インポートプランナー、競合ポリシー、順序付きエグゼキュータ。
- `src/runtime/`: MenuManager、FilePicker、コレクション、保存添付ファイル、注釈、ゴミ箱、全文インデックスに対する Zotero 10 アダプタ。
- `src/dialog.ts`: プレビュー、競合選択、進捗、完了の UI。
- `addon/`: manifest、XUL ダイアログ、CSS、アイコン。XPI のルートにコピーされます。
- `tests/`: 計画・競合処理・変更順序の振る舞いテストに加え、このビルドが実地で突き止めた XUL / chrome / メニューの配線を固定するソーステキストのアサーション。

## 互換性とプライバシー

- プラグイン ID: `folder-import@shuqi.local`
- Zotero: `10.0` から `10.0.*`
- ネットワーク通信なし、テレメトリなし、メタデータ検索なし。ファイルは取り込み先コレクション内の名前だけで照合され、内容が読まれることもハッシュ化されることもありません。
